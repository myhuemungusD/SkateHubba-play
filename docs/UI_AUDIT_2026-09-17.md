# UI Audit — 2026-09-17

## Scope and method

Signed-out production audit of `https://skatehubba.com` on 2026-09-17, using a live browser at a 390 × 844 mobile viewport and the default responsive viewport. This is a visual and interaction audit; authenticated game flows, camera/media permissions, notifications, and native binaries require separately provisioned test accounts/devices.

## Ship blocker

### Legal and data-deletion routes render the landing page

**Severity: P0 — compliance and user-trust blocker**

On production, activating the landing footer controls changes the address but does not render the requested page:

| Control | Requested URL | Observed content |
| --- | --- | --- |
| Privacy | `/privacy` | Landing page |
| Data Deletion | `/data-deletion` | Landing page |

The current source contains explicit React Router routes for both paths in `src/App.tsx`, so production is either serving a stale frontend bundle or a routing/deployment configuration is not matching the checked-in application.

### Acceptance criteria

- [ ] Visiting `/privacy`, `/terms`, and `/data-deletion` directly renders the correct document/screen on production.
- [ ] Landing footer controls render those routes without a full-page fallback.
- [ ] Add browser E2E coverage for direct navigation to all three routes and for each footer control.
- [ ] Confirm the production deployment revision matches the commit that contains the router definitions.
