# Apple App Store and Google Play release audit

Audit date: 2026-10-26. Source baseline: `7bdc966f48560e750f0c09b849761fdf0f0c5290`, `myhuemungusD/SkateHubba-play`, source version 1.2.0.

**Decision: not yet demonstrated ready to submit.** Native projects, release workflows and many compliance controls exist. That is not evidence of a processed signed binary, current backend configuration, completed console declarations or a successful two-phone game. No store submission, deployment, account deletion, production seed, paid Mac build or console setting change was performed in this review.

## Scope and evidence limits

Reviewed release workflows, package/lock configuration, native permissions/entitlements/privacy manifest, feature gates, auth and deletion, public policy surfaces, moderation/report/block paths, Firestore/Storage controls, API loading, release metadata and tests. Enumerated and mechanically scanned **all 87 tracked Markdown files** (1,395,414 bytes at baseline), checked relative Markdown link targets, and reconciled release-critical claims against source. This is a broad static review plus the validation below, not a proof that every source branch or every historical prose assertion is correct. [Markdown inventory](MARKDOWN_REVIEW_2026-10-26.md) records retained historical/generated documents and review depth.

Apple/Play/Firebase/Vercel consoles and physical devices were not available to this review. The GitHub connector returned no workflow runs for the exact baseline SHA; that is an evidence gap, not proof that workflows failed or never ran. Open issues #568, #517 and #338 were retrieved; their older claims are not treated as current runtime observations.

## Already implemented — do not reopen as missing features

- `/privacy`, `/terms`, `/data-deletion` have explicit React routes in `src/App.tsx`. Direct production rendering still needs a browser check; HTTP 200 alone would not prove the right screen.
- Account deletion has native-origin CORS, a recent-login requirement, server-side cascade and Auth deletion (`api/account/`). It is not merely client-side Firebase Auth removal. API dependency loading passes locally.
- Apple sign-in exists and is enabled by the iOS workflow. Firebase provider configuration and hide-my-email behavior still need device validation.
- Report/block UI, terms acceptance, text filtering, bans, moderation statements and appeals exist. Spot chat waits for the block list before rendering. Presence and existing-game interaction exceptions still need acceptance testing.
- Android no longer requests the retired SDK `tools` package. API 36 is configured. The old failure description in #568 is stale as a source finding.
- Native tester overrides are disabled by `isFeatureTesterOverrideActive()`. Off-by-default features cannot be unlocked by that web tester mechanism inside the store app.
- No broad Android media/storage or background-location permission is declared in the app manifest. Inspect the **merged release manifest** too; dependencies can add permissions.
- An iOS privacy manifest, camera/microphone/location/photo usage strings, Sign in with Apple and production push entitlements are present. Final archive validation remains required.
- Store flags keep Closet, Studio, drops, trading, Bucks purchase, Runner, dice, pro blessing, SMS enrollment and random challenger off. WTT must remain unticked for the public iOS binary. Do not make IAP setup or deferred games a blocker for this unchanged launch scope.

## Device acceptance matrix — same release SHA

Use an ordinary account, not a web feature tester, plus a separate reviewer account. Record device/OS, build number, result and evidence for each row on physical iPhone and Android.

1. Clean install and cold start; slow/offline startup; no permanent splash, blank screen or missing Firebase configuration.
2. Email signup, age rejection, terms acceptance, verification, reset and sign-in; Google sign-in on both platforms; Apple and hide-my-email on iOS. Test existing MFA accounts separately from disabled enrollment.
3. Two real users complete a challenge: set/record/upload, replay with sound, match/miss, result, review/dispute/referee, notification and rematch. Deny camera/mic, background during capture, interrupt upload, retry, delete a game and revoke access. Confirm understandable recovery and no duplicate game writes.
4. Notification permission denied/granted, foreground/background/terminated push and deep-link navigation. Confirm server delivery with real APNs/FCM tokens.
5. Map with location denied and granted; check-in and presence, private/crew spots, hide-online behavior and background expiry. Do not claim that hide-online hides spot presence: current policy describes the exception.
6. Public upload moderation, game-clip reports, text/profile/chat reports, blocking, moderator removal, reasons and appeals. Confirm blocked content never flashes before the block list loads.
7. Delete email, Google and Apple accounts after creating content across games, clips, chat, check-ins and devices. Verify server data/Auth deletion, sign-out, Apple revocation, processor erasure and retry behavior. Exercise old sessions and server errors. Read `/data-deletion` while signed out.
8. Disabled-feature routes stay inaccessible, no hidden purchase CTA, correct safe areas/keyboard, accessibility labels and usable text sizes. Inspect screenshots from the actual shipping experience.
9. Android: inspect all packaged native `.so` files and APK alignment for 16 KB support; test a 16 KB emulator/device. A high targetSdk or modern AGP does not prove every bundled library is compatible. Retain Play pre-launch report.

## Console and submission checklist

### Apple

- [ ] Membership, agreements, app record/bundle ID and submission access confirmed; migration state checked.
- [ ] Signed archive uses Xcode 26+ / iOS 26 SDK or later and finishes App Store Connect processing.
- [ ] Actual privacy report/SDK manifests, App Privacy answers, age rating, export compliance and territories reviewed.
- [ ] Working review account with access to all public features; notes explain asynchronous play and moderation. No MFA obstacle for reviewer access.
- [ ] Support/privacy URLs and accurate device screenshots; no claims for deferred features. Existing screenshot script captures a web viewport, which is not proof of native appearance.
- [ ] TestFlight acceptance completed before submission.

### Google Play

- [ ] Developer verification, agreements, app signing and package identity checked; service-account permissions verified.
- [ ] Signed API-36 AAB accepted with a fresh versionCode; merged permissions and native-library compatibility inspected.
- [ ] Data safety, account-deletion web URL, content rating, target audience, app access, ads and safety declarations completed for the real app.
- [ ] Check account type/date: personal accounts created after 2023-11-13 require at least 12 continuously opted-in testers for 14 days and approval for production access. Internal testing alone does not satisfy this.
- [ ] Confirm actual app category; complete Child Safety Standards if in scope. No covered-category policy URL/contact was established by this repo review.
- [ ] Internal/closed device tests and pre-launch report reviewed before production rollout.

### Both

- [ ] Backend rules/functions/indexes and environment match the release candidate; moderation/support owner and response procedure named.
- [ ] Preserve last-known-good web/backend revisions and native rollout controls. Stop/phased-rollout rollback is not an instant uninstall of shipped binaries.
- [ ] Monitor crashes, sign-in errors, App Check failures, upload/deletion failures, push delivery and reports after release.
